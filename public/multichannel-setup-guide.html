Phase 1 — Database
1
Run the database migration
Supabase SQL

Run this SQL in Supabase → SQL Editor. It adds the channel columns and makes phone nullable so Instagram/Facebook contacts (who have no phone number) can be stored.

-- Allow phone to be NULL for Instagram/Facebook contacts
ALTER TABLE contacts ALTER COLUMN phone DROP NOT NULL;

-- Store Instagram/Facebook sender PSIDs
ALTER TABLE contacts
  ADD COLUMN IF NOT EXISTS channel_user_id TEXT;

CREATE INDEX IF NOT EXISTS contacts_channel_user_id_business_idx
  ON contacts (channel_user_id, business_id);

-- Tag every conversation and message with its channel
ALTER TABLE conversations
  ADD COLUMN IF NOT EXISTS channel TEXT NOT NULL DEFAULT 'whatsapp'
  CHECK (channel IN ('whatsapp', 'instagram', 'facebook'));

ALTER TABLE messages
  ADD COLUMN IF NOT EXISTS channel TEXT NOT NULL DEFAULT 'whatsapp'
  CHECK (channel IN ('whatsapp', 'instagram', 'facebook'));

-- Add IG/FB identifiers to businesses
ALTER TABLE businesses
  ADD COLUMN IF NOT EXISTS ig_account_id TEXT,
  ADD COLUMN IF NOT EXISTS fb_page_id    TEXT,
  ADD COLUMN IF NOT EXISTS fb_page_token TEXT;
⚠️
Run this migration before testing any Instagram or Facebook messages. The phone DROP NOT NULL line is critical — without it, creating Instagram contacts will fail silently.
Phase 2 — Meta Business Suite
2
Create a System User
IG + FB

A System User generates a permanent token that never expires and isn't tied to any personal Facebook account. One System User covers all businesses and all channels.

  1. Go to business.facebook.com → Settings (gear icon) → Users → System Users
  2. Click Add → enter a name (e.g. whatsapp-agent-bot) → Role: Admin
  3. Click Create System User
ℹ️
Use Admin role, not Employee. Employee role cannot generate tokens with the permissions needed for messaging APIs.
3
Assign assets to the System User
IG + FB

Click Add Assets on the System User. You must assign all three asset types or the token will not have access.

  1. Apps — select your Meta App → give Full Control
    This is the same Meta App that handles your WhatsApp webhook.
  2. Pages — select each Facebook Page → give Full Control
    Missing this step causes #200 Requires pages_manage_metadata errors when subscribing Pages to the webhook.
  3. Instagram accounts — select each Instagram Business Account → give Full Control
🚫
If you skip assigning Pages, /me/accounts returns an empty array and you cannot subscribe the Pages to the webhook. You must assign Pages explicitly.
4
Generate the System User token
IG + FB

Click Generate New Token on the System User. Select your Meta App and tick all of these permissions:

PermissionRequired for
pages_manage_metadataSubscribing Pages to the webhook
pages_messagingSending/receiving Facebook Messenger messages
instagram_basicInstagram account access
instagram_manage_messagesSending/receiving Instagram DMs
whatsapp_business_messagingWhatsApp (if shown)
public_profileReading sender names
⚠️
Copy the token immediately — it is only shown once. This is your permanent System User token and will be stored in Supabase as access_token for both businesses.
✅
Verify it in developers.facebook.com → Tools → Access Token Debugger. The Expires field should say Never.
Phase 3 — Find your IDs
5
Find your Instagram Business Account ID
Instagram

The Instagram Business Account ID is not the numeric ID visible in the Instagram app URL. It is the ID of the Instagram account linked to your Facebook Page, obtained via the Graph API.

Open this URL in your browser (replace values, no curly braces):

https://graph.facebook.com/v19.0/{YOUR_FB_PAGE_ID}?fields=instagram_business_account&access_token={SYSTEM_USER_TOKEN}

Response:

{
  "instagram_business_account": {
    "id": "17841404274639707"   ← this is your ig_account_id
  },
  "id": "123456789"
}

Do this for each Facebook Page to get the ig_account_id for each business.

6
Find your Facebook Page IDs
Facebook
  1. Go to your Facebook Page
  2. Click About in the left menu
  3. Scroll to the bottom → Page ID is shown as a number

Alternatively, check the URL when editing the Page — the numeric ID appears in the path.

Phase 4 — Supabase configuration
7
Update Supabase businesses table
Supabase SQL

Run in Supabase → SQL Editor. Replace each value with your actual IDs and token. Both businesses use the same System User token.

-- Business 1 (replace name, IDs, and token)
UPDATE businesses
SET
  access_token  = 'SYSTEM_USER_TOKEN',
  ig_account_id = '17841404274639707',
  fb_page_id    = '123456789'
WHERE name = 'LegalAid AI';

-- Business 2
UPDATE businesses
SET
  access_token  = 'SYSTEM_USER_TOKEN',
  ig_account_id = '17841442470814607',
  fb_page_id    = '987654321'
WHERE name = 'Garment Retail';
ℹ️
Leave fb_page_token as NULL. The system falls back to access_token for sending Facebook replies, which works correctly with the System User token.
Phase 5 — Webhook subscriptions
8
Subscribe Instagram to the webhook
Instagram
  1. Go to developers.facebook.com → your Meta App → Instagram product → Webhooks
  2. Click Add Callback URL
    Use the same webhook URL and verify token as your WhatsApp setup. No new URL needed.
  3. Under Webhook Fields, tick messages → click Subscribe
  4. Under Instagram Accounts, connect both Instagram accounts
✅
Your webhook verify token is stored in Netlify → Site configuration → Environment variables as WEBHOOK_VERIFY_TOKEN.
9
Subscribe Facebook Pages to the webhook
Facebook

Facebook Messenger requires each Page to be individually subscribed to receive webhook events. This is the most commonly missed step.

  1. Go to Meta App → Messenger product → Settings
  2. Under Webhooks, add the same callback URL and verify token if not already set → subscribe to the messages field
  3. Under Access Tokens, click Add or Remove Pages → connect both Facebook Pages
  4. For each connected Page, click Edit Page Subscriptions → tick messages → Save
🚫
Do not generate a Page Access Token from the Messenger Access Tokens section and store it in fb_page_token. Tokens generated there are short-lived and will break message sending when they expire. Leave fb_page_token as NULL.
⚠️
If you regenerate a token in the Messenger Access Tokens section, it can disconnect the Page webhook subscription. If Messenger stops working, return here and re-tick the messages checkbox in Edit Page Subscriptions.
Phase 6 — Verify
10
Test and verify all channels
IG + FB
  1. Instagram test — send a DM to each Instagram Business Account from a personal account
    Expected: Netlify logs show [webhook/instagram] matched business: ... and the conversation appears in the dashboard with a 📸 IG badge.
  2. Facebook test — send a message to each Facebook Page via Messenger
    Expected: Netlify logs show [webhook] POST received — object: page and [webhook/facebook] matched business: ....
  3. Verify contact names — the first message creates a contact with the PSID as the name. The second message from the same account will self-heal to the real username/name.
    Or update manually in Supabase: UPDATE contacts SET name = 'real_name' WHERE channel_user_id = 'psid';
  4. Verify AI replies — the AI should auto-reply based on the business's ai_auto_threshold setting (same logic as WhatsApp).

Nothing appears in Netlify logs for Facebook?

  1. The Meta App must be in Live mode (not Development) for messages from the public to trigger webhooks
  2. Verify the Page is subscribed: open https://graph.facebook.com/v19.0/{PAGE_ID}/subscribed_apps?access_token={TOKEN} — it should return your app name, not an empty array
  3. Re-do Step 9 — re-tick the messages checkbox in Edit Page Subscriptions
